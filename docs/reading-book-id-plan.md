# 읽은 시간에 책 id 남기기 · `책 추가` 의 같은 제목

> 구현함(DB 버전 3, 2026-10-15). 상세의 동작은 모두 책 id 로(목록에 없던 책은 `BookShelf.claim`), 상세를 연 사이 바뀌었는지 보던 `BookRecord.shape` 확인은 걷어냈다. 테스트: `BookForTest`·`BookRecordAllTest`·`ReadingBookIdTest`·`DbMigrationTest`·`DbOpenTest`.

## 왜

- 읽은 시간 `reading_day` 는 `날짜 · 패키지/제목 · ms` 로만 남는다(`Reading.kt` `readingKey`). 어느 책인지는 보여 줄 때마다 제목으로
  다시 정한다(`BookRecord.all` 의 `accOf`: 지운 책(지운 날까지) → 읽고 있는 책 → 지우지 않은 나간 책 중 최근 → 목록에 없던 책).
- 그래서 같은 제목의 책이 새로 생기면 지난 시간이 옮겨 간다. 예: 1월에 『데미안』 A 를 60분 읽고 완독(나간 책) → 10월에 `책 추가` 로
  같은 제목 B 를 넣음(`BookShelf.add` 는 같은 제목의 나간 책을 보지 않고 새 책을 만든다) → 1월 60분도 B 로 간다. A 는 시간이 0,
  B 는 `1월 5일부터` 읽는 중. B 를 빼도 최근 나간 책이 B 라 A 로 돌아오지 않는다.
- 자동 추가(`addOpened`)는 같은 제목의 나간 책을 되살리므로(`findLivePast`) 이 일이 없다. `책 추가` 에서만 생긴다.

## 목표

1. 읽은 시간 줄마다 **책 id** 를 남겨, 한 번 정한 책은 그 뒤 같은 제목의 책이 생기거나 제목을 고쳐도 바뀌지 않게 한다.
2. `책 추가` 는 같은 제목의 나간 책이 있어도 늘 새 책(아래).
3. 이미 쌓인 기록도 마이그레이션에서 책 id 를 채운다.

## 비목표

- 같은 날·같은 앱에서 편 책을 모르는 채 같은 제목의 두 책을 읽은 시간 나누기(가를 수 없다).
- 저자로 같은 책 가르기(이북 앱이 저자를 안 주거나 `저 · 역` 이 붙어 글자가 달라 믿을 수 없다. 대신 `책 추가` 메뉴 머리에 저자를 보여 사용자가 판단).
- 기록 옮기기(`docs/backup-plan.md`)의 구현. 계획 문서만 맞춘다.
- 회차 규칙(5분 기준 등)은 바꾸지 않는다. 회차 계산은 책마다 모인 `dayMs` 를 그대로 쓴다.
- (받아들인 한계, 사용자 결정 2026-10-16: 너무 드물다) 제목만 아는 빈 시간(`book_id = ''`)이 그 제목의 새 책에 붙는지가 홈을 연 때에 따라 다르다:
  이미 저장된 날은 책이 생길 때 `adopt` 로 옮겨 가고, 아직 저장 전인 날은 `firstReadDays`(그 책이 아직 없던 날) 때문에 비어 남는다.
  이런 시간은 1.5.3 에서 올라온 옛 편 책 줄(10권이 차 못 넣은 책·지운 책)이나, 지운 책을 메뉴·서재 없이 하루를 넘겨 계속 읽을 때만 생긴다.

## DB: 버전 3 에 넣는다

- 릴리스된 판은 1.5.3 까지 DB 버전 2. 버전 3(회차)은 아직 이 브랜치에만 있으므로 **버전 4 를 만들지 않고 버전 3 에 더한다**.
  이 브랜치의 v3 가 깔린 곳(개발용 에뮬레이터 두 대)은 깨끗이 다시 깔고 시험 데이터를 v2 로 넣어 마이그레이션을 다시 거친다(되돌리기는 지원하지 않는다).
- `reading_day(day INTEGER NOT NULL, pkg TEXT NOT NULL, title TEXT NOT NULL DEFAULT '', book_id TEXT NOT NULL DEFAULT '', ms INTEGER NOT NULL, PRIMARY KEY (day, pkg, title, book_id))`
  + 색인 `reading_day_book (book_id)`.
  - 예전의 `key`(`패키지/제목` 한 칸)를 앱 `pkg`·편 책 제목 `title`(몰랐으면 `''`)로 나눈다. `book_id` 는 그 시간이 붙은 책 id, 모르면 `''`
    (NULL 을 쓰지 않는다. 기본 키에서 NULL 은 겹쳐도 막히지 않는다).
  - 기본 키가 바뀌므로 표를 새로 만들어 옮긴다(`reading_day_v2` 로 이름 바꾸기 → 새로 만들기 → 옮기기 → 지우기).
  - 메모리에서는 `ReadKey(pkg, title, book)`, `ReadingDays = Map<LocalDate, Map<ReadKey, Long>>`.
- `book_open(at INTEGER NOT NULL, pkg TEXT NOT NULL, title TEXT NOT NULL, book_id TEXT NOT NULL DEFAULT '')` — `ALTER TABLE ... ADD COLUMN`.
- `onCreate`(새 설치)는 새 꼴로 만든다. v1→v3, v2→v3, JSON 옮기기 모두 같은 채우기를 거친다.

## 책을 정하는 규칙 `bookFor(title, day, shelf, history): String?` (순수 함수, `Books.kt`)

지금 `accOf` 의 순서에 **나간 책의 나간 날**을 더한다. 그리고 그날 이미 있던 책만 본다: 그 책 id 가 붙은 읽은 시간이 처음 나오는 날(`firstReadDays`, 따로 저장하지 않음)이 그날보다 뒤면 아직 없던 책. 같은 제목 = `sameTitle(b.title, title)` 또는 `seenTitle` 의 `normTitle` 이 같음(지금과 같은 한 조건).

1. 나간 책(지운 책 포함) 중 같은 제목이고 `day <= 나간 날(left_at 의 그 지역 날짜)` 인 책이 있으면, 그중 `left_at` 이 가장 이른 책.
   - 지운 책을 지운 날로 나누던 지금 규칙(`forget` 이 `left_at` 을 지운 때로 바꾼다)을 지우지 않은 나간 책까지 넓힌 것이다.
   - 1월 20일에 나간 A, 10월에 들어온 B: 1월 5일 → A.
2. 읽고 있는 책 중 같은 제목인 첫 책(목록 앞쪽부터).
3. 지우지 않은 나간 책 중 같은 제목이고 `left_at` 이 가장 늦은 책(`findLivePast` 와 같음).
4. 없으면 null(목록에 없던 책 → `book_id = ''`).

이 규칙은 **책 id 를 정할 때만** 쓴다(아래 저장·마이그레이션). 정한 뒤에는 다시 정하지 않는다.
알고 있는 한계: 같은 제목의 두 책을 동시에 목록에 두고(하나는 나중에 나감) 읽은 날은 1번이 나간 책 쪽으로 붙인다. 드물다.

## 저장

- **편 책**: `ReaderWatchService.bookOpened` 는 이미 그 책을 찾거나(`findByTitle`) 넣는다(`addOpened`). 그 id 를 `ReadingLog.bookOpened(context, pkg, title, book, at)` 로 넘겨 `book_open.book_id` 에 적는다.
  (권수 제한을 없애 늘 넣으므로 id 가 늘 있다. 서비스가 꺼질 때는 앱마다 제목 없는 편 책을 적는다, `ReadingLog.watchStopped`.) 같은 책을 이어서 편 것인지 보는 조건(마지막 편 책과 같으면 안 적음)은 제목과 id 를 함께 본다.
  예전 `reader_watch` 설정에서 시작하는 편 책(`opened_<pkg>`)은 `''`.
- **센 시간**: `Counter.totals` 는 구간마다 그때의 편 책으로 `(key, book_id)` 를 붙인다. 메모리의 날마다 값 `ReadingDays` 는
  `Map<LocalDate, Map<ReadKey, Long>>`, `data class ReadKey(val pkg: String, val title: String = "", val book: String = "")` 로 바꾼다(표의 칸과 같다).
- **비어 있는 id 채우기**: `ReadingLog.days` 가 돌려주기 전, `book == ''` 이고 제목이 있는 칸은 `bookFor(제목, 그날, 지금 목록, 나간 책)` 으로 채운다.
  끝난 날은 이 값으로 저장되고(그 뒤 다시 정하지 않는다), 오늘은 부를 때마다 다시 센다(오늘 안에 책이 생기면 따라간다).
  채운 뒤 같은 `(key, book)` 이 겹치면 ms 를 더한다.
- **목록에 없던 책이 책이 되는 순간**(그 제목의 `book_id = ''` 줄을 그 책 id 로): `ReadingLog.adopt(context, title, seenTitle, bookId)`.
  - 부르는 곳: `BookShelf.keep`(목록에 없던 책의 상세에서 무엇이든 하는 순간 `BookShelf.claim` 이 그 책을 나간 책으로 적어 둘 때),
    `addOpened` 가 새 책을 만들 때. (`BookShelf.add`(책 추가)는 하지 않는다: 직접 넣은 책은 제목으로 잇지 않는다, 아래)
  - 같은 제목 비교는 `bookFor` 와 같은 조건. 날짜 제한 없이 모든 빈 줄. 겹치면 ms 를 더한다. DB 와 메모리 사본(`ReadingLog.cached`)을 함께 바꾼다.
- **예전 id 바꾸기**: `BookShelf.migrateIds`(1.2.1 까지의 YES24 번호·`auto-`·`legacy` → `b-`)가 목록을 저장할 때 같은 트랜잭션으로
  책 id 가 들어가는 모든 표의 옛 id 를 새 id 로 바꾼다: `reading_day.book_id`·`book_open.book_id`·`finish.book_id`·`review.book_id`·`round_start.book_id`.
  (바꾸기가 실패하면 옛 id 로 계속 쓰다 다음에 읽고 있는 책 목록을 읽을 때 다시 하므로, 그 사이 옛 id 로 쌓인 완독·감상·회차 시작·읽은 시간이 끊기지 않게.
  그 사이 나간 책은 옛 id 그대로 남는다 — 읽고 있는 책만 바꾸고, 옛 id 로도 기록은 다 이어진다)
- **잠금·순서**: `ReadingLog.days`(채우기·저장)와 `adopt` 는 같은 잠금(`ReadingLog` 의 `@Synchronized`)으로 하나씩 한다.
  `adopt` 는 BookShelf 의 저장 트랜잭션(`atomic`) 안에서 부른다(실패하면 함께 되돌려진다). 잠금 순서는 늘 BookShelf → ReadingLog:
  `days` 는 ReadingLog 잠금을 잡기 전에 BookShelf 목록(`list`·`history`)을 읽어 두고, 잠금 안에서는 BookShelf 를 부르지 않는다. DB 쓰기가 성공한 뒤에만 메모리 사본을 바꾸고,
  실패하면 사본을 비워 다음에 DB 에서 다시 읽는다.

## 보여 줄 때

- `BookRecord.all(context, days)`: `book != ''` 인 칸은 그 id 의 책에 모은다(읽고 있는 책 → 그 상태, 나간 책 → 나간/지운 책). 그 id 가
  목록·나간 책 어디에도 없으면(있어서는 안 되지만) 다른 책에 붙이지 않고 목록에 없던 책(그 제목)으로 보인다.
  `book == ''` 칸은 목록에 없던 책(`TITLE_ONLY + normTitle`)으로.
  더는 제목으로 책을 찾지 않는다(`accOf` 의 지운 날·우선순위 규칙이 빠진다).
- 독서 기록의 `이번 주 읽은 책`(`ReadingActivity.byBook`): 책 id 로 모으고 이름은 그 책의 지금 제목, `''` 은 제목 그대로.
- 합계·연속일·링·그래프는 책을 보지 않으므로 그대로(`total`).

## 마이그레이션 채우기 (`Db.upgrade`)

- 옛 `reading_day` 줄을 새 표로 옮기면서 제목이 있는 줄은 `bookFor(제목, 그날, shelf, past)` 로 채운다(옛 표에는 책 id 가 붙은 시간이 없어 처음 읽은 날 `firstReadDays` 는 쓰지 않는다: 모든 책을 그날 있던 책으로 본다. 받아들인 예외). shelf·past 는 같은 트랜잭션에서
  SQL 로 읽는다(`BookShelf` 캐시를 쓰지 않는다). 없으면 `''`. 패키지만 있는 줄(JSON 시절의 앱별 합계 등)은 `''`.
- `book_open` 은 칸만 더한다(`''`). 끝나지 않은 날은 저장할 때 채운다.
- JSON 옮기기(1.2.1 까지): `reading.json` 은 앱별 합계라 제목이 없어 모두 `''`. 순서: 표 만들기 → JSON 넣기 → 채우기.

## `책 추가` 의 같은 제목 (`BookSearchActivity.pick`)

- 처음에는 같은 제목의 나간 책이 있으면 `이어서 읽기` / `다른 책으로 넣기` 를 묻기로 했으나, **늘 새 책으로 넣기로 바꿨다**(사용자 결정:
  직접 책 추가는 거의 쓰지 않고, 이어 읽기는 자동 추가·상세의 `다시 읽기` 가 한다. 책 id 로 나눠 두니 새 책이 지난 시간을 가져가지 않는다).
- (바뀜, 사용자 결정) `책 추가` 는 지원하지 않는 이북 앱용이다. 직접 넣은 책(id `m-`, `ShelfBook.manual`)은 제목으로 찾지 않는다(`hasTitle` 이 false: 자동 추가·`bookFor`·`claim`·`adopt` 모두).
  그 제목의 어느 책에도 붙지 않은 시간(`book_id = ''`)도 가져오지 않는다(지원하는 앱에서 읽은 시간이라 자동 추가가 넣은 책의 것). 1.5.3 까지 넣은 책(`b-`)은 예전처럼.

## 자동 추가가 꺼져 있던 시간: '책 모름' 줄 (A)

사용자 규칙: 자동 추가(접근성 서비스 `ReaderWatchService`)가 꺼져 있던 동안 읽은 시간은 책 없이 시간만(하루 합계·연속일에는 들어간다. 책만 모를 뿐 시간은 유효).

- 읽은 시간은 나중에 사용 기록에서 세고 책은 그 시각에 그 앱의 마지막 편 책 줄(`book_open`)로 붙인다. 그래서 "여기부터 책 모름" 을 편 책 기록에 제목·책 id 가 빈 줄로 적는다.
  셀 때 마지막 줄이 빈 줄이면 그 시간은 `reading_day` 에 제목 없이 들어간다. 새 표·칸은 없다.
- 빈 줄을 적는 때:
  1. 서비스가 꺼질 때(`onUnbind` → `ReadingLog.watchStopped`, 앱마다). 접근성 설정에서도 꺼진 때(사용자가 끔)는 그 자리에서. 업데이트·재부팅처럼 설정은 켜진 채 떨어지면 다시 붙을 때 끊긴 때로(4).
  2. 서재에서 제목을 못 읽은 칸을 눌러 들어갈 때(`unknownOpen`, 그 앱. 메뉴의 제목을 읽으면 그 책 줄이 이어서 적힌다).
  3. 셀 때(`ReadingLog.days`) 서비스가 이 프로세스에 붙어 있지 않으면(`ReaderWatchService.bound`. 설정에서 꺼짐, 켜져 있어도 시스템이 떼어 놓음·저절로 꺼지는 기기), 지금이 아니라 꺼진 때로(`ReaderWatchService.stoppedAt`: 정상적으로 끊겼으면 끊긴 때,
     끊김 알림 없이 끝났으면 살아 있던 것이 확실한 마지막 때 = 연결된 때·이북 앱 알림을 마지막으로 받은 때·편 책을 마지막으로 적은 때(`ReadingLog.lastOpenAt`) 중 늦은 것).
  4. 서비스가 다시 붙을 때(`onServiceConnected`) 내려가 있던 시작으로(`downSince`: 정상적으로 끊겼으면 끊긴 때, 끊김 알림 없이 끝났으면 — 강제 종료·메모리 부족·업데이트·재부팅 — 살아 있던 마지막 때).
  마지막 알림 시각은 서비스가 이미 남기는 기록(`WatchLog` 앱마다 마지막 알림)이라 새 쓰기는 없다. 몇 초 늦게 저장하므로 실제보다 이를 수 있는데,
  그러면 '책 모름' 이 넓어질 뿐 다른 책에 붙지는 않는다(사용자 결정: 모르면 버린다).
  이미 마지막 줄이 빈 줄이면 다시 적지 않는다.
- 남는 한계(받아들임):
  - 알림 없이 꺼지면 마지막 알림 뒤에 실제로 같은 책을 계속 읽은 시간도 '책 모름' 이 된다(앞 책에 잘못 붙이는 대신 버린다). 업데이트·재부팅 뒤에도 같다
    (다시 붙은 뒤 이북 앱이 마지막 책을 바로 열면 서재·메뉴에서 제목을 볼 때까지 책 모름). 이미 저장한 지난날은 다시 세지 않는다.
  - 서비스가 켜져 있어도 이북 앱이 서재를 거치지 않고 다른 책으로 가면(다음 권·알림으로 열기) 메뉴의 제목이 보일 때까지 이전 책에 붙는다(이 작업 전부터).
  - 꺼졌다 다시 켠 뒤 이북 앱이 마지막 책을 바로 열면 서비스가 제목을 볼 때까지 책 모름이 이어진다.
  - 서비스가 못 본 시간을 나중에 다시 같은 책을 펴서 앞뒤로 메우는 것(추측)은 하지 않는다(사용자 결정).
- 검토하고 버린 안: 서비스가 본 읽기만 책에(B′, 읽는 화면마다 '봤음' 줄·종류 칸·켜질 때 화면 확인 — 드문 경우에 비해 크다),
  관찰 세션 × 사용 기록 교집합(10~30초마다 생존 기록 — 주기적 쓰기를 하지 않기로 함), 안드로이드 프로세스 종료 기록(API 30+ — 버전 처리를 하지 않기로 함).

## 테스트 (Robolectric, `app/src/test`)

- `bookFor`: 1~4 순서, `day == 나간 날` 경계, 나간 책 여럿(먼저 나간 책), 지운 책, `seenTitle` 만 같음, 읽고 있는 책과 나간 책이 함께 있을 때.
- 마이그레이션: v1·v2 → v3 에서 `reading_day` 가 새 키로 옮겨지고 책 id 가 채워짐(같은 제목 A 나간·B 읽는 중 → 1월은 A, 10월은 B), 패키지만 있는 줄 `''`, JSON 옮기기 `''`, 새 설치 꼴.
- `adopt`: 빈 줄을 채움, 겹치는 칸 더하기, 다른 제목은 그대로, 메모리 사본도, DB 실패 시 사본을 비움.
- `migrateIds`: 옛 id 의 `book_id` 가 다섯 표 모두 새 id 로. 첫 바꾸기가 실패해 옛 id 로 완독·감상을 남긴 뒤 다시 바꿔도 이어짐.
- `책 추가` 의 누를 때 상태 표: 저장 함수 단위(`restore`·`add` 의 반환과 결과)로.
- `BookRecord.all`: id 로 모음(같은 제목 새 책이 지난 시간을 가져가지 않음, 제목을 고쳐도 따라감), `''` 은 목록에 없던 책, 지운 뒤 같은 제목 → 다시 보임.
- `ReadingLog.days` 의 채우기(오늘은 다시 정하고 끝난 날은 저장된 값 유지)는 사용 기록이 필요해 `totals` 에 편 책 목록을 넣는 단위로 시험.

## 순서

1. 지금 회차 작업을 커밋한다.
2. DB(v3 에 칸·표 다시 만들기)·`bookFor`·마이그레이션 채우기·`migrateIds` + 테스트.
3. 저장 경로(편 책 id, 빈 id 채우기, `adopt`) + 보여 주기(`BookRecord.all`, `byBook`) + 테스트.
4. `책 추가` 메뉴: 시안 → 정하면 구현.
5. 문서, 에뮬레이터 두 대(v2 데이터로 다시)에서 마이그레이션·같은 제목 흐름 확인.
