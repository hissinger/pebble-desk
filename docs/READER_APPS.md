# 이북 앱 분석 노트 (크레마 페블)

Pebble Desk 가 이북 앱에서 무엇을 알아내고 무엇을 할 수 있는지 조사한 기록이다.
방법: 기기에 깔린 앱의 매니페스트·디컴파일 코드(jadx), 기기의 사용 기록(`dumpsys usagestats`)·알림·저장소 목록, 커널·이벤트 로그.
2026-10 기준 버전. 실제로 실행해 보지 않은 것은 **(미확인)** 으로 표시했다. 사용자는 주로 **교보도서관·밀리의서재** 를 쓴다.

## 자동 추가: 앱별로 가져오는 것

설정 › 독서 › `자동 추가 안내` 의 앱별 안내(`ReaderGuide`)가 이 절을 사용자 말로 줄여 보인다(2026-10-22). 화면에는 어디서 오는지는 적지 않고 `자동으로 들어오는 책 정보` 로 들어오는지만 적고, 안 들어오는 것은 이유(앱이 막고 있음·구독·내 파일)를 함께 적는다. 여기에는 앱마다 같은 틀로 자세히 적는다.

- **권한**: 그 앱에 필요한 안드로이드 권한.
- **할 것**: 그 이북 앱에서 바꿔 둘 설정·보기 방식, 책을 여는 길.
- **표지 · 제목 · 저자 · 진행률 · 반납일**: 어디서(서재 칸·읽는 화면·메뉴·파일) 가져오는지, 못 가져오면 왜인지.
- **제약**: 그 밖에 알아 둘 것.

근거는 이 문서의 앱별 절과 DESIGN.md `읽는 책 자동 추가`. 요소 이름은 거기에 있다.

### 모든 앱 공통

- **권한**
  - 읽는 책 자동 추가 = 안드로이드 접근성에서 Pebble Desk 켜기. 모든 앱에 필요하다(KOReader 도: 앱이 앞에 오는 것을 이것으로 안다).
  - 오늘 읽은 시간 = 사용 기록 액세스. 책별로 나누는 것은 자동 추가가 켜져 있어야 한다(꺼진 동안 읽은 시간은 책 없이 하루 합계·연속일에만). Libby 는 읽는 화면이 요소라 자동 추가가 꺼져 있으면 시간도 세지 않는다.
  - 책 파일 읽기 = 모든 파일에 액세스. KOReader 는 꼭 있어야 하고, 문리더·네오리더·이지뷰어·채리뷰어는 표지(이지뷰어·채리뷰어는 책 정보도)를 책 파일에서 꺼낼 때, Readest 는 데이터 폴더를 공유 저장소로 옮겼을 때 그 데이터를 읽을 때 쓴다. 다른 앱은 쓰지 않는다.
- **표지**: 표지가 없는 책이 서재 화면에 보이면 그 칸의 표지 그림을 화면 캡처에서 잘라 온다(서재 썸네일 크기라 홈에서 크게 보면 조금 흐리다). 서재가 1.5초 그대로일 때 자르고, 서재를 잠깐만 보는 앱(알라딘·북커스·YES24 전자도서관·YES24 eBook·문리더·밀리 휴대폰 판·킨들·Libby)은 보이는 대로 1초에 한 번 자른다. 목록에 없는 책의 표지도 잘라 두었다가(제목별 최근 12권, 메모리) 그 책을 펴면 붙인다. 화면 캡처(`AccessibilityService.takeScreenshot`)는 안드로이드 11 부터라 안드로이드 9·10 에서는 화면에서 자르는 표지가 모두 빈 표지다(책 파일·앱 데이터에서 꺼내는 표지는 들어온다. 자동 추가 안내도 9·10 에서는 표지 줄을 그렇게 바꿔 보인다, `ReaderGuide.Info.coverBefore11`). 표지를 못 가져오면 빈 표지로 그리고, 책 상세 › `책 정보 고치기` › `표지 다시 찾기`(인터넷 표지 검색, 한국어는 YES24)로 바꾼다.
- **제목**: 서재에서 누른 칸, 또는 읽는 화면 메뉴의 제목. 사용자가 고친 제목은 앱이 보인 제목(`seen_title`)으로도 알아봐 되돌아가지 않는다.
- **저자**: 비어 있을 때만 채운다. 직접 넣거나 고친 저자는 덮지 않는다. 저자를 보이지 않는 앱은 직접 넣는다(같은 메뉴의 `저자 입력`).
- **진행률**: 화면에 보일 때만 바뀐다. 읽는 화면의 값을 서재보다 믿는다(서재 값이 늦는 앱은 서재 값을 쓰지 않는다).
- **반납일**: `반납 4일 남음`·`D-15`·`14일 남음`·`만료일: 14일` 을 본 날짜로 셈해 날짜로 저장하고, 홈·목록은 그날에 맞춰 `반납 N일 남음`·`오늘 반납`·`반납 기한 지남` 으로 보인다. 서재에 반납이 보이는 대여 앱만 있다.

### 교보도서관 `kr.co.kyobobook.KEL`

- **권한**: 공통만.
- **할 것**: 뷰어 설정 › `뷰어 하단 정보 표시` 를 `독서 진행률` 이 든 것(`독서 진행률` · `독서 진행률, 페이지 번호`)으로 둔다(`정보 표시 없음` 이면 아래 줄이 `- %` 라 읽는 중 진행률이 들어오지 않는다). 선택지는 교보eBook 과 같다(2.2.6 APK 문자열, 2026-10-22). 서재는 목록 보기를 권한다.
- **표지**: 목록 보기 서재 칸의 표지를 잘라 온다. 표지 보기 칸에는 제목이 없어 어느 책의 표지인지 몰라 자르지 않는다.
- **제목**: 목록 보기 서재에서 누른 칸(읽는 화면이 열릴 때 편 것으로 본다. 받지 않은 칸은 누르면 받기만 해, 받기만 한 책은 들어오지 않는다). 표지 보기 서재로 연 책은 읽는 화면에서 메뉴를 띄우면 위 막대의 제목으로 들어온다.
- **저자**: 목록 보기 서재 칸.
- **진행률**: 서재 칸(`47%`), 읽는 화면 아래 줄(뷰어 하단 정보 표시에 독서 진행률이 있을 때).
- **반납일**: 서재 칸 `반납 4일 남음`.
- **제약**: 표지 보기 서재에서는 읽다가 메뉴를 띄워야 책이 들어온다.

### 교보도서관 보기 방식 (2026-10-05)

- `정렬` 메뉴의 보기방식: 목록 보기(기본) / 표지 보기. 둘 다 `MainActivity`, 칸 요소 이름은 같다(`ivThumbnail`, `tvRemainDate`, `tvReadPercentageTxt`).
- **표지 보기 칸에는 제목(`tvTitle`)·저자가 없다.** 반납은 `4일` 처럼 짧게, 표지 그림에 설명 글(contentDescription)도 없다. 칸을 누르면 `[4일, 47%]` 클릭이 온다.
- → 표지 보기 서재에서는 어떤 책인지 알 수 없다. (표지 그림 특징값으로 목록의 책과 맞춰 보는 것은 해 봤고 되지만, 추측이라 넣지 않기로 했다.) 대신 읽는 화면의 메뉴 제목으로 안다(아래 교보eBook).

### 교보 읽는 화면 (교보도서관·교보eBook 공통, 2026-10-05)

- 본문은 웹 화면(`WebView`)이고, 위아래 막대는 이름 있는 일반 요소다. 웹 화면 안을 훑지 않고 이름으로만 찾을 수 있다.

### 밀리 탭별 (2026-10-05)

- 다운로드·전체도서 탭은 `bookshelf.BookshelfActivity`, 책장 > 읽고있는 책 등은 `bookshelf.BookShelfDetailActivity`. 칸의 요소 이름은 모두 같다(`tv_book_title`, `iv_thumbnail`, `bookshelf_cell_reading`). 보기 방식(목록/격자) 설정은 없다.
