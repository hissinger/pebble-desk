# 기록 옮기기(내보내기·가져오기) 계획

상태: 계획만. 아직 구현하지 않는다.

## 왜

- `allowBackup="false"` 라 앱을 지우거나 기기를 바꾸면 기록(DB·표지·설정)이 모두 사라진다.
- 옮겨야 하는 경우는 둘이다.
  1. **기기 교체**: 새 기기(비어 있음)로 옮긴다.
  2. **여러 기기 중 하나 정리**: 그만 쓸 기기의 기록을 계속 쓸 기기(기록 있음)에 합친다.
- 둘 다 **한쪽 기기를 그만 쓰는 한 번의 이동**이다. 여러 기기를 계속 맞추는 동기화는 하지 않는다(서버·계정이 필요하고, 전자잉크 기기에는 클라우드 앱이 없는 경우가 많다).
- 같은 기능이 백업도 겸한다(내보낸 파일을 두었다가 다시 깔고 가져오기).

## 하지 않는 것

- 안드로이드 자동 백업(`allowBackup`·`dataExtractionRules`): 구글 백업 전송이 있어야 하고 크레마·메이북에서 동작을 장담할 수 없으며 시점을 정할 수 없다.
- 서버·클라우드·기기 간 직접 전송(와이파이·QR).
- 여러 번 오가는 양방향 동기화(같은 파일을 두 번 가져오는 것은 막는다).

## 사용 흐름

1. 그만 쓸 기기: 설정 › `기록 내보내기` → 저장할 곳 고르기(SAF `ACTION_CREATE_DOCUMENT`). 기본 이름 `PebbleDesk-기록-<yyyyMMdd>.zip`.
2. 파일을 옮긴다(USB 로 PC, SD 카드 등. 사용자 안내는 TROUBLESHOOTING 에).
3. 받는 기기: 설정 › `기록 가져오기` → 파일 고르기(`ACTION_OPEN_DOCUMENT`).
4. 확인 창: 무엇이 들어오는지 숫자로 보여 준다. 예: `책 12권(3권은 이미 있는 책에 합침) · 완독 5번 · 읽은 시간 34시간 · 별점 4개`. `가져오기` / `취소`.
5. 끝나면 결과 한 줄(`가져왔습니다`). 실패하면 아무것도 바뀌지 않는다.

교체·합치기를 사용자가 고르지 않는다. 가져오기는 한 가지 규칙(아래 `합치기`)으로 돌고, 받는 기기가 비어 있으면 결과가 그대로 넣기와 같아진다.

## 파일 형식

zip 하나.

| 경로 | 내용 |
|---|---|
| `manifest.json` | `format`(1), `exportId`(UUID), `exportedAt`, `appVersion`, `dbVersion`, 기기 모델 |
| `data.json` | 표마다 행 배열: `shelf`·`past`·`finish`(줄 id 는 빼고 `uid` 로)·`review`·`round_start`·읽은 시간(`days`) · `since` · 하루 목표 이력 |
| `settings.json` | `home.xml` 중 옮길 값(아래 `설정`) |
| `covers/<id>.jpg` | 책 표지 원본만(`files/books/<id>.jpg`). 줄인 표지(`<id>_…t….png`)는 받는 기기에서 다시 만든다 |

- DB 파일을 통째로 복사하지 않고 JSON 으로 쓴다: DB 판이 달라도 읽을 수 있고 합치기가 쉽다.
- `format` 이 앱이 아는 것보다 높으면 가져오지 않는다(`새 판 앱에서 만든 파일입니다. 앱을 업데이트해 주세요`).
- 읽은 시간은 DB 에 저장된 날뿐 아니라 **오늘 센 몫까지**(`ReadingLog.days`) 넣는다. 오늘은 DB 에 저장하지 않기 때문이다(`Reading.kt` `days`).
- 받는 기기에서 가져온 시간(`reading_import`)도 더해서 내보낸다(옮긴 기록을 다시 옮겨도 이어지게).

## 지금 DB 에서 지워지는 것(합치기 규칙의 근거)

| 표 | 지우는가 | 비고 |
|---|---|---|
| `shelf`·`past` | 표를 통째로 다시 쓰지만 책은 사라지지 않는다 | 읽고 있는 책 ↔ 나간 책으로 옮겨 다님. 올해 읽은 책에서 지우기는 `hidden = 1`(표지 파일만 지움) |
| `finish` | 지우지 않음(키는 기기마다 따로 매긴 줄 `id`, 같은 날 두 번 완독도 따로. 회차의 시작한 날·별점·감상은 고칠 수 있다) | 더하기만. 같은 완독은 `uid` 로만 알아본다(아래 `완독한 날`) |
| `round_start` | 완독하면 지움(그 완독 줄의 `started` 로 옮김) | 아래 `다시 읽기한 날` |
| `review` | 별점·감상을 둘 다 비우면 행을 지움. 완독하면 그 회차(`finish`)로 옮기고 지움(완독하지 않은 마지막 회차의 것만 남는다) | "비웠다"와 "없었다"를 구별할 수 없다 |
| `reading_day` | 날마다 통째로 다시 씀 | 어제까지(`through`)는 고정, 그 뒤 날은 사용 기록으로 다시 세어 **덮어쓴다** |
| `book_open` | 10일쯤 지난 것은 지움(앱마다 마지막 한 권은 남김) | 그 기기의 읽은 시간 나누기에만 쓰는 값 |

## 합치기

받는 기기를 **기준**으로 둔다. 가져온 것은 받는 기기에 없는 것을 더하는 쪽으로만 쓴다.

### 같은 책 찾기

- 책 id 는 기기마다 새로 만든 UUID(`b-…`, 직접 넣은 책은 `m-…`)라 같은 책도 id 가 다르다.
- 제목(`sameTitle`·`normTitle`, 또는 `seenTitle`)과 저자로 짝을 짓는다. 저자가 한쪽에 비어 있으면 제목만으로. 짝이 지어지면 가져온 책의 id 를 받는 기기 책의 id 로 바꿔 끼운다(완독·별점이 따라온다).
- 짝이 없으면 가져온 id 를 그대로 쓴다(UUID 라 겹치지 않는다).
- `책 추가` 로 직접 넣은 책(`m-…`, 지원하지 않는 이북 앱용)은 제목으로 짝짓지 않는다(앱에서도 제목으로 다른 책·읽은 시간과 잇지 않는다). id 가 같을 때만 같은 책(같은 기기에서 내보낸 것을 다시 가져올 때).

### 표마다

| 무엇 | 규칙 |
|---|---|
| 읽고 있는 책 | **받는 기기에 읽고 있는 책이 없으면** 가져온 목록을 그대로 쓴다(교체). **있으면 합치지 않는다**: 가져온 읽고 있는 책 중 짝이 있는 책은 기록만 합치고, 없는 책은 `뺀 책`(나간 책, `left_at` = 가져온 때)으로 넣는다 |
| 나간 책 | 짝이 있으면 받는 기기 상태(읽는 중·뺀 책·지운 책)를 그대로 둔다. 없으면 가져온 행을 `hidden` 까지 그대로 더한다. 순서는 `left_at` 순 |
| 완독한 날 | 합집합. 같은 완독은 `uid`(DB 버전 3 부터 완독마다 무작위로 매기고 기기를 옮겨도 그대로)로 알아본다. 회차 순서는 (완독한 날, 누른 때 `at`), 둘 다 같으면 줄 id 다. `at` 을 그대로 옮기면 같은 날 두 완독의 순서도 그대로다(둘 다 같은 경우는 버전 3 전의 완독뿐인데 그때는 하루에 하나였고, 같은 ms 에 두 번 완독할 수는 없다). 줄 id 는 기기마다 따로 매긴 번호라 쓰지 않는다: `book_id` 를 바꿔 끼우고 받는 기기에 없는 `uid` 만 새 줄(받는 기기가 새 id)로 넣는다. 있으면 시작한 날·별점·감상은 받는 기기에 없을 때만 가져온 것. 회차를 지우게 되면 지운 `uid` 를 남겨(지운 완독 목록) 가져오기가 되살리지 않게 한다 |
| 다시 읽기한 날(진행 중 회차 표시) | 받는 기기에 없을 때만. 받는 기기에서 그 뒤 완독했으면 버린다: 날이 있으면 그날 뒤의 완독이 있을 때, 날이 없으면(1.5 판에서 다시 읽던 책) 가져온 기기의 마지막 완독(`uid`) 뒤에 받는 기기에 완독이 더 있을 때. 아니면 날 없는 표시도 그대로 둔다 |
| 별점·감상 | 받는 기기에 있으면 받는 기기 것. 없으면 가져온 것(받는 기기에서 일부러 비운 별점이 살아날 수 있으나 드물어 받아들인다) |
| 읽은 시간 | 같은 날·앱·제목·책끼리 **더한다**. 칸의 `book_id` 는 위 책 짝짓기로 받는 기기의 id 로 바꿔 끼운다(짝이 없어 새로 넣은 책은 그 id, 비어 있으면 비운 채). 저장은 아래 `reading_import` |
| 기록 시작일(`since`) | 둘 중 이른 날 |
| 하루 목표 이력 | 받는 기기 것. 받는 기기에 이력이 없는 지난날만 가져온 이력으로(연속일·목표 달성이 원래 기기와 같게) |
| 표지 | 받는 기기 책에 표지가 없을 때만 가져온 표지 |

### 읽은 시간은 따로 둔다: `reading_import`

- `reading_day` 에 바로 더하면, `through` 다음 날(오늘 포함)은 사용 기록으로 다시 세어 통째로 덮어써 가져온 몫이 사라진다(`saved.days + counted`).
- 그래서 DB 버전 4 에 `reading_import (day, pkg, title, book_id, ms, PRIMARY KEY (day, pkg, title, book_id))`(`reading_day` 와 같은 꼴)를 더하고, 가져온 시간은 여기에만 쓴다. `ReadingLog.read` 에서 `reading_day` 에 더해 읽는다(연속일·링·그래프가 모두 합친 값을 본다).
- 가져온 시간을 되돌려야 하면 이 표만 비우면 된다.

### 두 번 가져오기 막기

- 가져온 `exportId` 를 `reading_meta`(`imported`, 쉼표로 이음)에 적는다. 같은 id 면 `이미 가져온 파일입니다` 로 멈춘다.
- 자기 기기에서 내보낸 파일을 다시 가져와도 같은 방법으로 막는다(내보낼 때 `exportId` 를 `reading_meta` `exported` 에도 적는다).

### 설정

- 받는 기기가 **처음 상태**(읽고 있는 책·나간 책·읽은 시간이 없음)일 때만 `설정도 가져올까요?` 를 묻는다. 아니면 받는 기기 설정을 그대로 둔다.
- 옮기는 값: 하루 목표, 주 시작 요일, 24시간 시계, 색(`palette`), 아이콘·상단 바 보이기, 목록/격자 보기, 영어, 글자 크기·줄 간격.
- 자주 쓰는 앱(`favorite_list`·`favorite_names`)·숨긴 앱(`hidden`)은 **받는 기기에 깔린 패키지만** 남긴다.
- 옮기지 않는 값: `onboarded`(받는 기기의 시작하기 상태 그대로).

### 옮기지 않는 것

- `book_open`: 그 기기에서 읽은 시간을 책으로 나누는 데만 쓴다. 이미 `reading_day` 로 나뉜 결과를 옮긴다.
- `reading_meta` 의 `through`: 받는 기기의 사용 기록 기준이다.
- 앱 목록 캐시 `apps.json`, 줄인 표지, 아이콘 캐시, 업데이트 파일.

## 안전

- 가져오기 전체를 DB 트랜잭션 하나로. 표지는 먼저 임시 이름으로 풀고, DB 가 성공하면 이름을 바꾼다. 실패하면 임시 파일을 지운다.
- 가져오기 직전 받는 기기의 기록을 앱 안(`files/backup/before-import-<시각>.zip`)에 하나 남긴다(마지막 하나만). 되돌리기는 이 파일로 가져오기 대신 **그대로 넣기**를 하는 것으로 충분하다(화면은 나중에 필요하면).
- zip 은 크기·항목 수 상한을 두고, 경로에 `..` 이 있으면 거절한다. 표지는 그림으로 열리는지 확인한다(`saveCover` 와 같게).

## 화면

- 설정의 어느 절에 둘지(`정보`? `기록`?)는 정하지 않았다.
- 확인 창은 아래 메뉴(`Sheet`)로. 숫자 줄과 `가져오기`/`취소`.
- 전자잉크라 진행 표시는 글자 한 줄(`가져오는 중…`)만.

## 문서

- TROUBLESHOOTING: `기기를 바꿨는데 기록이 없습니다` → 이전 기기에서 내보내기, 파일 옮기는 방법(USB·SD 카드), 가져오기.
- DESIGN.md: 메뉴 위치·확인 창.
- CLAUDE.md: 저장 구조에 `reading_import`, DB 버전 4(버전 3 은 회차마다 별점·감상).

## 시험

에뮬레이터 두 대(`CremaPebble_A11` 두 벌, 또는 페블 + `Tango_A14`).

1. 빈 기기로 가져오기: 읽고 있는 책 순서·표지·완독 도장·별점·연속일·4주 달력이 원래 기기와 같은지.
2. 기록 있는 기기로 합치기: 읽고 있는 책은 그대로, 가져온 책은 뺀 책 또는 기존 책에 합쳐짐, 같은 날 읽은 시간이 더해짐.
3. 오늘 읽은 시간이 있는 상태로 가져온 뒤 홈을 몇 번 오가도 합친 시간이 줄지 않는지(`reading_import`).
4. 같은 파일 두 번, 자기 파일 가져오기 → 막힘.
5. 중간 실패(표지 하나를 깨뜨린 zip) → 아무것도 바뀌지 않음.
6. 새 `format` 파일을 이전 판 앱에서 → 거절.
7. 자주 쓰는 앱에 받는 기기에 없는 앱이 있을 때.

## 정할 것

- 메뉴 위치와 이름(`기록 내보내기`/`기록 가져오기`, 또는 `기록 옮기기` 한 줄 아래 두 메뉴).
- 가져오기 직전 자동 백업을 둘지(위 제안).
- 같은 책 찾기에서 애매한 경우(제목만 같고 저자가 다름)를 묻을지, 다른 책으로 둘지(제안: 다른 책으로).
